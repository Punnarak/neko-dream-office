# 🐾 Neko Dream Office

ออฟฟิศแมวพาสเทลที่แสดงสถานะการทำงาน **จริง** ของ Claude Code (Terminal / VS Code) แบบ real-time
เปิดค้างไว้ข้าง VS Code ได้ ใช้ทรัพยากรน้อย ไม่มีข้อมูลจำลองในโหมด Live

```
Claude Code hooks ──POST──▶ Node backend (127.0.0.1:4777) ──WebSocket──▶ React Cat Office
                            เก็บสถานะใน memory                    อัปเดตทันทีไม่ต้อง refresh
```

## ติดตั้ง

ต้องมี Node.js 20+ และ Claude Code 2.1+

```bash
cd ~/workspace/neko-dream-office
npm install
npm run build            # สร้างหน้าเว็บ (ทำครั้งเดียว หรือทุกครั้งที่แก้ไฟล์ใน web/)
npm run hooks:install    # เพิ่ม hooks ใน ~/.claude/settings.json (สำรองไฟล์เดิมให้อัตโนมัติ)
```

`hooks:install` จะ:
- สำรอง `~/.claude/settings.json` เป็น `settings.json.bak-neko-<เวลา>` ก่อนแก้ทุกครั้ง
- **เพิ่ม** hook ต่อท้าย ไม่แก้/ลบ hook เดิม (rtk, pith ฯลฯ ยังทำงานตามปกติ)
- รันซ้ำได้ (ไม่ซ้อนกัน)

Session ของ Claude Code ที่เปิดอยู่ก่อนติดตั้งอาจต้องปิดแล้วเปิดใหม่จึงจะส่ง event

## คำสั่งใน Claude Code (ง่ายสุด)

| คำสั่ง | ทำอะไร |
|---|---|
| `/neko-start` | เปิด backend เบื้องหลัง (build/ติดตั้ง hooks ให้ถ้ายังไม่มี) แล้วเปิดเบราว์เซอร์ — `/neko-start --no-open` ไม่เปิดเบราว์เซอร์ |
| `/neko-status` | ดูว่า backend รันอยู่ไหม และ hooks ติดตั้งแล้วหรือยัง |
| `/neko-stop` | ปิด backend (hooks ยังอยู่ — Claude ทำงานปกติ) |
| `/neko-uninstall` | ปิด backend + ลบ hooks (สำรอง settings ก่อน) — ไม่ลบโฟลเดอร์โปรเจกต์ |

ไฟล์คำสั่งอยู่ที่ `~/.claude/commands/neko-*.md` เรียก `scripts/neko.sh start|stop|status|uninstall` ซึ่งใช้จาก terminal ตรงๆ ได้เช่นกัน

## เปิด / ปิด (แบบ manual)

```bash
npm start                # เปิด backend + หน้าเว็บ → http://127.0.0.1:4777
# ปิด: Ctrl+C
```

โหมดพัฒนา (แก้ UI แล้วเห็นทันที): `npm run dev:server` + `npm run dev:web` แล้วเปิด http://127.0.0.1:5173

โหมด Demo (ข้อมูลจำลอง ดู UI โดยไม่ต้องมี Claude Code): http://127.0.0.1:4777/?demo=1
— มีแถบเหลืองใหญ่ "DEMO MODE" และป้าย DEMO ตลอดเวลา, โค้ด demo ไม่ถูกโหลดในโหมด Live
— ในโหมดนี้มีลูกแมวจำลอง: Main, subagent `Explore` ที่เดินไปโต๊ะต่าง ๆ และ `Plan` ที่โผล่มาสั้น ๆ (ตัวเลข tokens ก็จำลอง)

## สถานะที่แสดง และ event ที่ทำให้เกิด

| สถานะ | มาจาก event | ความหมาย |
|---|---|---|
| **Idle** | `SessionStart`, `Notification(idle_prompt)` | เปิด session แล้ว / รอคำสั่ง |
| **Working** | `UserPromptSubmit`, `PostToolUse` | กำลังคิด/ทำงานระหว่างเทิร์น |
| **Using Tool** | `PreToolUse` | มีเครื่องมือกำลังทำงาน (แสดงชื่อ) |
| **Needs You** | `Notification(permission_prompt)` | รอคุณกดอนุญาต |
| **Error** | `PostToolUseFailure`, `StopFailure` | เครื่องมือล้มเหลว / เทิร์นจบเพราะ API error |
| **Interrupted** | `PostToolUseFailure` ที่ `is_interrupt=true` | คุณกดหยุดกลางคัน (ไม่นับเป็น error) |
| **Turn Completed** | `Stop` | Claude ตอบจบเทิร์น — *ไม่ได้แปลว่างานสำเร็จ* |
| **Stopped** | `SessionEnd` | ปิด session แล้ว (แสดง reason จาก hook) — ลูกแมวทุกตัวออกจากห้อง |
| ลูกแมว subagent เข้าห้อง | `SubagentStart` (มี `agent_id`, `agent_type`) | มี subagent เริ่มทำงาน |
| ลูกแมวย้ายโต๊ะ | `PreToolUse` / `PostToolUse` ที่มี `agent_id` (ไม่มี = Main) | agent นั้นเริ่ม/จบการใช้เครื่องมือ |
| ลูกแมว subagent ออกจากห้อง | `SubagentStop`, `Stop`, `StopFailure`, `SessionEnd` | subagent จบงาน หรือเทิร์น/session จบ |
| **Disconnected** | WebSocket หลุด | หน้าเว็บติดต่อ backend ไม่ได้ — ข้อมูลที่เห็นถูกทำให้จางและติดป้าย "ข้อมูลก่อนหลุด" |
| **Waiting for Events** | ยังไม่มี event | backend ทำงานอยู่แต่ยังไม่มี session ส่งข้อมูลมา |
| *เงียบ X นาที* | ไม่มี event เกิน 10 นาที | ไม่เดาสถานะ เช่น ปิด terminal แบบ kill จะไม่มี `SessionEnd` |

ไม่มีเปอร์เซ็นต์ความคืบหน้า เพราะ hooks ไม่มีข้อมูลนี้

## ตัวละคร: ลูกแมว = AI agent จริง, แมวโต = หัวหน้าโต๊ะ

### ลูกแมว (agent จริง)

ลูกแมวตัวเล็ก 1 ตัว = agent 1 ตัวที่กำลังทำงานจริงใน session ที่เลือก

- **Main** (แมวดำใส่มงกุฎทอง ป้ายสีทอง) = agent หลักของ session มีตลอดจนกว่า session จะปิด
- **subagent** (ลูกแมวสีพาสเทลใส่ปลอกคอ) ป้ายชื่อเป็น `agent_type` เช่น `Explore`, `Plan`, `general-purpose` — เข้าห้องเมื่อ `SubagentStart` และออกเมื่อ `SubagentStop` หรือเมื่อ `Stop` / `StopFailure` / `SessionEnd`
- ระหว่างใช้เครื่องมือ ลูกแมวจะไปนั่งข้างโต๊ะของหมวดเครื่องมือนั้น (เช่น Grep → โต๊ะ Luna) ถ้าไม่มีเครื่องมือทำงานจะรออยู่บนพรมกลางห้อง
- ถ้ามีหลายตัวที่โต๊ะเดียวกันจะเรียงแถวไม่ทับกัน (Main อยู่หน้าสุด แล้วเรียงตามเวลาที่เริ่ม)
- การย้ายโต๊ะมีแอนิเมชันเลื่อนเฉพาะเมื่อระบบไม่ได้ตั้ง `prefers-reduced-motion`
- คลิกลูกแมวเพื่อดูประเภท, เครื่องมือที่ใช้อยู่ + สรุปสั้น, เวลาที่ทำงานมา, จำนวน tool calls และ event ล่าสุด
- **ไม่เดา:** tool event ที่ไม่มี `agent_id` นับเป็นของ Main เสมอ และไม่สร้าง agent ขึ้นเอง
  ถ้าเห็น tool event ที่มี `agent_id` ที่ไม่รู้จัก (เช่น backend เพิ่ง restart ระหว่าง subagent ทำงาน) จะแสดงลูกแมวตัวนั้นพร้อมข้อความ "ไม่ทราบเวลาเริ่ม"
- สีขนของ subagent เป็นการตกแต่ง (สุ่มจาก id) ไม่มีความหมาย
- **ความอ้วน = tokens ที่ agent นั้นใช้จริง** (ยิ่งใช้มากยิ่งอ้วน) — แมวโต 6 ตัวไม่เปลี่ยนหุ่น เพราะเป็นโต๊ะหมวดเครื่องมือ ไม่ใช่ agent

### ลูกแมวอ้วน/ผอมตาม tokens

- **ที่มา:** hook ทุกตัวส่ง `transcript_path` (transcript ของ Main) และ `SubagentStop` ส่ง `agent_transcript_path` — transcript ของ subagent อยู่ที่ `<session>/subagents/agent-<agent_id>.jsonl`
  backend อ่านไฟล์ JSONL เหล่านี้แล้วรวม `message.usage` ของคำตอบแต่ละอัน (นับซ้ำไม่ได้: Claude Code เขียนคำตอบเดียวหลายบรรทัด จึง dedupe ด้วย `message.id` / `requestId`)
- **ตัวเลขที่ใช้วัด:** `input + output + cache_creation` — **ไม่นับ** `cache_read` (คือ prompt เดิมที่อ่านซ้ำจาก cache ทุกเทิร์น ตัวเลขใหญ่มากและไม่ใช่การ "กิน" tokens ใหม่) แต่แสดงแยกไว้ในรายละเอียด
- **ระดับ** (ตั้งจาก transcript จริงในเครื่องนี้: subagent ส่วนใหญ่ 50k–200k, Main ส่วนใหญ่ 70k–900k):

  | tokens | หุ่น |
  |---|---|
  | < 20k | ผอมเพรียว |
  | 20k – 100k | หุ่นปกติ |
  | 100k – 300k | จ้ำม่ำ (มีพุงขาว) |
  | 300k – 1M | กลมป๊อก |
  | ≥ 1M | กลมดิ๊กมาก |

- ยังไม่รู้ตัวเลข (ยังไม่มี hook event หลัง backend เริ่ม หรือไฟล์อ่านไม่ได้) = หุ่นปกติ + "ยังไม่ทราบ" — ไม่เดาตัวเลข
- คลิกลูกแมวเพื่อดู "ใช้ไป 12.3k tokens" + แยก input / output / cache เขียน / cache อ่านซ้ำ (ไม่นับ)
- **ความปลอดภัย:** อ่านเฉพาะไฟล์ `.jsonl` ที่ realpath อยู่ใน `~/.claude/projects`, เก็บเฉพาะตัวเลขใน `usage` — ไม่เก็บ/ส่ง/log เนื้อหาข้อความ prompt หรือผลลัพธ์เครื่องมือ
- **ทรัพยากร:** อ่านต่อจาก byte เดิม (ไม่อ่านทั้งไฟล์ซ้ำ), อ่านไฟล์ละไม่เกิน 1 ครั้งต่อ 3 วิ (`NEKO_USAGE_INTERVAL=วินาที`) และอ่านเฉพาะตอนมี hook event — ไม่มี polling
  ตัวเลขจึงอัปเดตตามจังหวะ event: Main ที่รอ subagent อยู่จะไม่โตจนกว่าจะมี event ของตัวเอง

### แมวโต 6 ตัว (หัวหน้าโต๊ะ ไม่ใช่ AI agent)

แต่ละตัวนั่งประจำโต๊ะและสรุปโต๊ะของตัวเอง: เครื่องมือในหมวดนั้นที่กำลังทำงาน **จริง** + จำนวนลูกแมวที่นั่งอยู่ เช่น Luna: `Read · 2 agents`
ส่วน Nori สรุปทั้ง session รวมจำนวน agent เช่น `Using Tool · 3 agents`

| แมว | บทบาท | โต๊ะนี้รับเครื่องมือ |
|---|---|---|
| Nori | Manager | สถานะรวมของ session + จำนวน agent (เครื่องมืออื่นที่ไม่เข้าหมวดไหนก็มานั่งโต๊ะนี้) |
| Mochi | Coding | Edit · Write · NotebookEdit |
| Miso | Research | WebSearch · WebFetch · MCP tools |
| Luna | Data | Read · Grep · Glob |
| Pudding | Creative | Agent (ตอนสั่งงาน subagent) |
| Pixel | QA | Bash |

- **ชิปสถานะ** (มีจุดสีด้านหน้า) = ข้อมูลจริงจาก hooks
- ท่านอน zzz, ดาว, ต้นไม้ = ตกแต่งเท่านั้น
- คลิกแมวโตเพื่อดู session, เครื่องมือที่กำลังทำงาน, error ล่าสุด, เหตุการณ์ของหมวดนั้น
- แถบด้านบนแยกแต่ละ session ตาม `session_id` — ค่าเริ่มต้นติดตาม session ที่มี event ล่าสุด, คลิกแท็บเพื่อปักไว้

### เปลี่ยนสัตว์ (⚙️ → สัตว์ในห้อง)

เลือกได้ 🐱 แมว (ค่าเริ่มต้น) · 🐶 หมา · 🐰 กระต่าย · 🐻 หมี · 🦊 จิ้งจอก — ใช้กับทั้งห้อง (หัวหน้าโต๊ะ 6 ตัว + ลูกทุกตัว)

- **เปลี่ยนแค่รูป:** หู หาง จมูก/ปาก — ท่าทาง สถานะ ความอ้วนตาม tokens มงกุฎ/ปลอกคอ และของบนโต๊ะเหมือนเดิมทุกอย่าง
- ชื่อบทบาทเปลี่ยนตาม เช่น "Coding Cat" → "Coding Dog" ส่วนชื่อ (Mochi, Miso…) คงเดิม · ไอคอนแท็บด้านข้างเปลี่ยนตามสัตว์
- หางหมาส่ายเฉพาะตอนมี tool ทำงานจริง (เหมือนอุ้งเท้าเคาะ) และไม่ขยับถ้าเครื่องตั้ง reduce motion
- เก็บใน localStorage `neko.animal` ของเบราว์เซอร์นี้ · โค้ดอยู่ที่ `web/src/animals.js` + ส่วนประกอบใน `components/Cat.jsx` (เพิ่มสัตว์ใหม่ = เพิ่ม 1 รายการ + หู/หาง/ปาก)

## เสียงแจ้งเตือน

กดปุ่ม **🔕 เสียงปิด** ที่มุมขวาบนเพื่อเปิดเสียง ค่าเริ่มต้นคือปิด และหน้าเว็บจะจำค่าที่เลือกไว้ เสียงสร้างด้วย Web Audio API ไม่มีไฟล์เสียง

| เมื่อ | เสียง | มาจาก event |
|---|---|---|
| Claude รอคุณตอบหรืออนุญาต | "เมี้ยว?" สองโน้ตไล่ขึ้น | `Notification` → Needs You |
| Error | โน้ตต่ำลงสั้น ๆ | `PostToolUseFailure`, `StopFailure` (ไม่รวมการกดหยุดเอง) |
| ทำงานเสร็จ (จบเทิร์น) | กระดิ่งดังเดียว | `Stop` |

- **เลือก session:** ดังได้ทุก session หรือเฉพาะ session ที่ดูอยู่
- **ไม่ดังถี่:** แต่ละ session ดังได้ไม่เกิน 1 ครั้งต่อ 3 วินาที แต่เสียงที่สำคัญกว่าจะแทรกได้
- **ดังเฉพาะ event ใหม่:** ไม่ดังตอนโหลดหน้า, refresh หรือ reconnect และไม่ดังทุกครั้งที่ใช้เครื่องมือ
- **หลังเปิดหน้าใหม่:** เบราว์เซอร์จะยอมให้มีเสียงหลังคลิกหรือกดปุ่มบนหน้าเว็บ 1 ครั้งก่อน
- **เปิดแท็บค้างไว้ได้:** ถ้าแท็บยังเปิดอยู่ แม้ถูกซ่อนอยู่หลังแท็บอื่น ก็ยังมีเสียง

## งาน Redmine ของฉัน

แผงด้านข้างมีการ์ด **📋 งานของฉัน** แสดง issue ที่ยังเปิดอยู่และ assign ให้คุณ ส่วนกระดานไม้ก๊อกในห้องจะบอกจำนวนงานและจำนวนงานที่เลยกำหนด

- **ตั้งค่า:** backend อ่าน env `REDMINE_URL` และ `REDMINE_API_KEY` ถ้าไม่มี จะอ่านไฟล์ `~/.config/neko-dream-office/redmine.json` (`{"url":"…","apiKey":"…"}`) แทน ไฟล์นี้ควร `chmod 600`
  - ถ้าเปิดด้วย `/neko-start` จะได้ env จาก `~/.claude/settings.json` ไปด้วยเลย
  - ถ้าเปิดด้วย `npm start` จาก terminal เอง ต้อง export env เองหรือใช้ไฟล์ config
- **การดึงข้อมูล:**
  - backend เป็นคนดึง โดยใช้ `issues.json?assigned_to_id=me&status_id=open` ได้สูงสุด 50 งาน API key จะไม่ถูกส่งไปที่หน้าเว็บ
  - ดึงตอนเปิดหน้าเว็บ และดึงซ้ำทุก 5 นาที (ตั้งค่าได้ด้วย `NEKO_REDMINE_INTERVAL=วินาที` ขั้นต่ำ 60)
  - ถ้าไม่มีใครเปิดหน้าเว็บอยู่จะไม่ดึง
  - ปุ่มรีเฟรชกดได้ 1 ครั้งต่อ 30 วินาที
- **ข้อมูลที่ส่งไปหน้าเว็บ:** เลข issue, หัวข้อ (≤120 ตัวอักษร และ redact แล้ว), project, tracker, สถานะ, priority, วันครบกำหนด, % และ `lastActivity` (เวลา + ของฉันไหม + ประเภทการแก้) — **ไม่ส่ง** description, comment, ชื่อคน หรือไฟล์แนบ
- **ความถูกต้องของข้อมูล:**
  - แสดงเวลาที่ดึงข้อมูลล่าสุดเสมอ
  - ถ้าดึงไม่สำเร็จ จะขึ้น error และทำรายการเดิมให้จาง
  - ข้อมูล Redmine **ไม่มีผล** กับท่าทางหรือสถานะของแมว
- **ป้ายวันครบกำหนด:** สีแดง = เลยกำหนดแล้ว, สีส้ม = ครบกำหนดภายใน 2 วัน
- **ปุ่ม 📋 คัดลอกคำสั่ง:** แต่ละงานมีปุ่มคัดลอกข้อความ `ตรวจสอบ Redmine #<เลข>` ไว้ให้นำไปวางใน Claude Code เอง หน้าเว็บแค่คัดลอกข้อความ **ไม่ได้สั่ง Claude หรือรันอะไรเลย**

### 🔗 Commit ↔ ลงเวลา (แท็บ ⏱)

แสดงงานที่ **สัปดาห์นี้ (จ.–วันนี้) มี commit แต่ยังไม่ได้ลงเวลาใน Redmine เลยในสัปดาห์นี้** — แสดงเฉพาะงานที่ยังไม่ลง ถ้าลงครบจะพับไว้และขึ้น "ครบ" (ใช้ตรรกะเดียวกับ skill dev-work-report)

- **รายการ repo + git author:** อ่าน `~/.config/neko-dream-office/git.json` (`{"author":"your.name","repos":["/path/repo", …]}`) ถ้าไม่มีจะใช้ `repos` + `git_author` จาก `~/.claude/skills/dev-work-report/config.json` (อ่านอย่างเดียว อ่านแค่ 2 ช่องนี้) ถ้าไม่มีทั้งคู่ ส่วนนี้จะไม่แสดง
- **วิธีอ่าน commit:** `git log --all --no-merges --author=…` ในเครื่อง (ไม่ใช้เน็ต, ไม่ fetch) ทีละ 3 repo, timeout 10 วิ/repo, กรองตามวันที่เขียน (author date) และนับ commit ซ้ำข้าม branch ครั้งเดียว — รันพร้อมรอบดึง Redmine (ทุก 5 นาทีตอนเปิดหน้าเว็บ)
- **รูปแบบเลขงานที่จับได้:** `Task #104498:`, `Defect #106873 :`, `REDMIND-87507,89635`, `REDMIND-[88371,88303]`, `Task # 85804,85805`, `#93602[New Loan]…`, `[#97472][SIT]…` — `#` เปล่าๆ ต้องมี 5–6 หลัก (`#3141`, `review #42`, `OPay#5` ไม่นับ)
- **นับว่าลงแล้ว:** ลงเวลางานนั้นวันไหนก็ได้ในสัปดาห์นี้ (commit วันหลังจากที่ลงเวลาไม่ถือว่าผิด) — ไม่มีสถานะ "commit หลัง log"
- ปุ่ม **⏱ ลงเวลา** เปิดฟอร์ม `issues/<เลข>/time_entries/new` ของ Redmine ในแท็บใหม่ โดย**กรอกไว้ให้**: วันที่ = วันที่ commit ล่าสุด, ชั่วโมง = เวลาที่ Claude ทำงานนั้นในวันนั้น (ถ้ามี), activity = activity ที่คุณใช้บ่อยสุด (ไม่ใช่ Leave) — **หน้าเว็บไม่ได้ลงเวลาให้** ต้องตรวจแล้วกดบันทึกเอง
- เลขงานที่ Redmine ไม่คืนมา ขึ้น "ไม่พบใน Redmine" (เลขผิด หรือไม่มีสิทธิ์ดู)
- **ข้อมูลที่ส่งไปหน้าเว็บ:** เลขงานที่ยังไม่ลง, ชื่อโฟลเดอร์ repo, จำนวน commit, วันที่ commit, จำนวนงานที่ commit อ้างทั้งหมด — **ไม่ส่ง** ข้อความ commit, ชื่อ author หรือ path เต็มของ repo

### 🔀 Resolved แล้วแต่ branch ยังไม่ merge (แท็บ 📋)

งานที่ assign ให้คุณและสถานะเป็น Resolved / รอปิด แต่ยังมี branch ที่มีงานนั้นอยู่และ**ยังไม่ merge เข้า branch หลัก** ของ repo — กันลืมก่อนขึ้น SIT/UAT

- **repo ที่ดู:** รายการเดียวกับหัวข้อก่อนหน้า (`git.json` หรือ config ของ dev-work-report) ไม่มี config = ไม่แสดง
- **วิธีดู (ในเครื่องเท่านั้น ไม่ใช้เน็ต, ไม่ `git fetch`):** ทีละ 3 repo, timeout 10 วิ/คำสั่ง — รันพร้อมรอบดึง Redmine และเฉพาะเมื่อมีงาน Resolved
  - branch หลัก: `git symbolic-ref --short refs/remotes/origin/HEAD` ถ้าไม่มีใช้ตัวแรกที่มีจาก `origin/master`, `origin/main`, `master`, `main`
  - branch ที่ยังไม่ merge: `git branch -a --no-merged <หลัก>` (ข้าม `origin/HEAD`, ชื่อ local กับ `origin/` เดียวกันนับครั้งเดียว, ไม่เกิน 300 branch/repo)
  - งานของ branch: เลข 5–6 หลักในชื่อ branch (`ticket/212` ไม่นับ) + เลขงานในข้อความ commit ที่มีเฉพาะใน branch นั้น `git log <หลัก>..<branch> --no-merges` (จำนวน = ahead)
  - ผลขึ้นกับว่าเครื่องนี้ fetch ล่าสุดเมื่อไร — ถ้ามีคน merge บน server แล้วแต่ยังไม่ได้ fetch จะยังขึ้นว่าไม่ merge
- **ที่หน้าเว็บ:** ป้าย **🔀 ยังไม่ merge** บนงานในกลุ่มรอปิด (ชี้ดู repo · branch · ahead N commits) และแถว "🔀 Resolved แต่ยังไม่ merge N งาน" ในการ์ด ☀️ วันนี้
- **ปุ่ม 📋 คัดลอกขอ merge:** คัดลอกข้อความขอ merge พร้อมส่ง — บรรทัดทักทาย, หัวข้องาน, ลิงก์ Redmine ของงาน แล้วตามด้วย 1 บรรทัดต่อ branch: branch ชื่อ `ticket/<เลข>` เป็นลิงก์ ticket ของ repo บน git server, branch อื่นเป็น `<repo>: <branch>` (คำทักทายและ URL ของ git server ตั้งเป็นค่าคงที่ใน `web/src/office.js`) — หน้าเว็บแค่คัดลอก **ไม่ได้ส่งให้ใคร**
- **ข้อมูลที่ส่งไปหน้าเว็บ:** `unmerged: {เลขงาน: [{repo, branch, base, ahead}]}` — ชื่อโฟลเดอร์ repo, ชื่อ branch (≤60 ตัวอักษร), ชื่อ branch หลัก และจำนวน commit ไม่เกิน 5 branch ต่องาน — **ไม่ส่ง** ข้อความ commit, ชื่อ author หรือ path เต็ม

### วันหยุดนักขัตฤกษ์ และวันลา

- **วันหยุด (ไฟล์):** backend อ่าน `~/.config/neko-dream-office/holidays.json` ถ้ามี (ไม่สร้างให้อัตโนมัติ) และอ่านใหม่เองเมื่อไฟล์ถูกแก้ (ดู mtime ตอนเปิดหน้าเว็บ และทุก ~1 นาทีระหว่างเปิดหน้าเว็บ) ไม่ต้อง restart
  ```bash
  mkdir -p ~/.config/neko-dream-office
  cp holidays.example.json ~/.config/neko-dream-office/holidays.json
  # แล้วแก้ไฟล์: เพิ่มวันหยุดทางจันทรคติ (มาฆบูชา วิสาขบูชา อาสาฬหบูชา เข้าพรรษา), วันหยุดชดเชย และวันหยุดบริษัท
  ```

  `holidays.example.json` มี **เฉพาะวันหยุดราชการไทยที่วันที่ตายตัวของปี 2026** (1 ม.ค., 6 เม.ย., 13–15 เม.ย., 1 พ.ค., 3 มิ.ย., 28 ก.ค., 12 ส.ค., 13 ต.ค., 23 ต.ค., 5 ธ.ค., 10 ธ.ค., 31 ธ.ค.) — วันหยุดตามจันทรคติและวันหยุดชดเชยต้องเพิ่มเอง
- **วันลา (จาก Redmine, อัตโนมัติ):** time entry ที่ activity ชื่อ `Leave` (ตรงตัว — กติกาเดียวกับ `is_leave` ของสคริปต์ dev-work-report) ทำให้วันนั้น (`spent_on`) เป็นวันลา — backend ส่ง `time.leaveDays: [{date, hours}]` (เฉพาะวันที่และชั่วโมง ไม่ส่ง comment) ในช่วงเดียวกับที่ดึง time entry; แสดงเป็นลายเฉียงพร้อมป้าย **🏖 ลา (Redmine)** และกดปิดจากหน้าเว็บไม่ได้ (ต้องแก้ใน Redmine) — ชั่วโมง Leave ยัง **นับรวม** ในยอด วันนี้/สัปดาห์/เดือน และกราฟตามเดิม ตัดออกเฉพาะจาก "ยังไม่ลง log" และค่าเฉลี่ยต่อวันทำงาน
- **วันลา (ต่อเบราว์เซอร์):** ในแท็บ ⏱ แตะแท่งของวันนั้น แล้วกด **🏖 วันลา/วันหยุด** (กดซ้ำเพื่อยกเลิก) — เก็บใน `localStorage` (`neko.daysOff`) ของเบราว์เซอร์นี้เท่านั้น ไม่ส่งไป backend
- ลำดับเมื่อซ้ำวันกัน: วันหยุด (ไฟล์) > ลา (Redmine) > วันลาที่กดเอง
- วันหยุด + วันลา: ไม่นับเป็น "ยังไม่ลง log", ไม่นับในค่าเฉลี่ยต่อวันทำงาน (แม้วันนั้นจะลงเวลาไว้), แสดงเป็นลายเฉียงในกราฟพร้อมชื่อวันหยุด

### 📅 ปฏิทิน iCal ในการ์ด "วันนี้"

แสดงนัดของวันนี้จากปฏิทิน `.ics` (Outlook / Exchange, Google Calendar หรือไฟล์ในเครื่อง) ไว้บนสุดของการ์ด

- **ตั้งค่า:** สร้าง `~/.config/neko-dream-office/calendar.json` แล้ว `chmod 600` (ลิงก์ iCal เป็นความลับ ใครมีลิงก์ก็อ่านปฏิทินได้) แล้ว restart backend
  ```json
  {"calendars": [
    {"name": "งาน", "url": "https://…/calendar.ics"},
    {"name": "ส่วนตัว", "file": "~/calendars/me.ics"}
  ]}
  ```
  - Outlook: Settings → Calendar → Shared calendars → **Publish a calendar** → คัดลอกลิงก์ **ICS**

  - `webcal://` ใช้ได้ (แปลงเป็น `https://`) · สูงสุด 5 ปฏิทิน
- **แสดง:** เวลา–ชื่อนัด–สถานที่ · นัดที่ผ่านไปแล้วจาง/ขีดฆ่า (ถ้าเกิน 6 นัดจะพับเหลือ "ผ่านไปแล้ว N นัด") · กำลังประชุมเป็นสีเขียว **ตอนนี้** · เริ่มภายใน 15 นาทีขึ้น **อีก N นาที** · นัดทั้งวันอยู่บนสุด
  หัวการ์ดมีชิป 📅 เวลานัดถัดไป (หรือ "ประชุมอยู่") เห็นได้แม้พับการ์ด · หลังเวลาเตือนก่อนเลิกงานหรือหมดนัดวันนี้แล้ว จะบอกนัดแรกของ **พรุ่งนี้**
- **รองรับ:** DTSTART/DTEND/DURATION, ชื่อเขตเวลา IANA และแบบ Windows (`SE Asia Standard Time` …), VTIMEZONE, นัดซ้ำ RRULE (DAILY / WEEKLY / MONTHLY / YEARLY + INTERVAL, COUNT, UNTIL, BYDAY, BYMONTHDAY, BYMONTH), EXDATE, นัดที่ถูกย้ายเฉพาะครั้ง (RECURRENCE-ID), ข้ามนัดที่ `STATUS:CANCELLED`
- **ความเป็นส่วนตัว:** backend ดึงเอง (timeout 15 วิ, ไม่เกิน 5 MB) ส่งให้หน้าเว็บแค่ เวลาเริ่ม/จบ, ชื่อนัด, สถานที่ (ตัดสั้น + redact) และชื่อปฏิทิน ของวันนี้กับพรุ่งนี้ — **ไม่ส่ง** URL, รายละเอียด, ผู้เข้าร่วม หรือลิงก์ประชุม; error บอกแค่สาเหตุ (เช่น `HTTP 401`) ไม่มี URL
- **🔔 เตือนก่อนประชุม** (⚙️ → เตือนก่อนประชุม: ปิด / 1 / 5 (ค่าเริ่มต้น) / 10 / 15 นาที — ตัวเลือกนี้โผล่เมื่อตั้งค่าปฏิทินแล้ว): เด้งแจ้งเตือนบนเดสก์ท็อป **ครั้งเดียวต่อนัด** (ชื่อนัด, เวลา, สถานที่ — ค้างจนกว่าจะกด) + เสียง "เมี้ยว?" ถ้าเปิดเสียงไว้ · ไม่นับนัดทั้งวัน · จำนัดที่เตือนแล้วใน localStorage `neko.meetDone` (reload ไม่เด้งซ้ำ ถ้านัดถูกเลื่อนเวลา/เปลี่ยนชื่อจะเตือนใหม่) · ตรวจทุก 20 วิ ต้องเปิดหน้าเว็บค้างไว้ ไม่เด้งในโหมด demo หรือตอนหลุดการเชื่อมต่อ
- **ความถี่:** ดึงทุก 15 นาที (`NEKO_CALENDAR_INTERVAL` วินาที) เฉพาะตอนเปิดหน้าเว็บ และดึงใหม่หลังเที่ยงคืน · ดึงไม่สำเร็จจะคงนัดเดิมของวันนั้นไว้และขึ้น ⚠ ในการ์ด

## Tokens รายวัน (แท็บ 🪙)

แผงด้านข้างมีแท็บ **🪙 โทเคน**: ชิป วันนี้ / สัปดาห์นี้ (จ.–อา.) / เดือนนี้ / เฉลี่ยต่อวัน (เฉพาะวันที่มีการใช้) + กราฟแท่ง 28 วัน (แตะแท่งเพื่อดูตัวเลขวันนั้น)

- **ที่มา:** transcript จริงทุกไฟล์ใน `~/.claude/projects` (ทั้ง main และ subagent ทุกโปรเจกต์) — ใช้ตัวอ่านเดียวกับลูกแมว (เฉพาะ `.jsonl` ที่ realpath อยู่ใน `~/.claude/projects`, เก็บเฉพาะตัวเลข usage + id + เวลา)
- **นับ:** `input + output + cache_creation` (เหมือนความอ้วนของลูกแมว), `cache_read` แสดงแยกและไม่นับ
- **ไม่นับซ้ำ:** คำตอบเดียวกันนับครั้งเดียวด้วย `message.id` / `requestId` แม้จะอยู่หลายไฟล์ (เช่น session ที่ resume)
- **แบ่งวัน:** ตาม `timestamp` ของแต่ละคำตอบ เป็นวันตามเวลาท้องถิ่นของเครื่องนี้
- **ทรัพยากร:** สแกนครั้งเดียวตอน backend เริ่ม (เบื้องหลัง ข้ามไฟล์ที่ไม่ถูกแก้ในช่วงนั้น — บนเครื่องนี้ 284 ไฟล์ ~410 MB ใช้ ~2 วิ) แล้วอ่านต่อจาก byte เดิมทุก ~60 วิ **เฉพาะตอนมีหน้าเว็บเปิดอยู่** (และหลัง `Stop` แต่ไม่ถี่กว่านั้น) ตั้งได้ด้วย `NEKO_TOKENS_INTERVAL=วินาที` (ขั้นต่ำ 30) — เก็บ id ไม่เกิน 200,000 รายการ, ไฟล์ไม่เกิน 5,000 ไฟล์
- ดูตัวเลขดิบ: `curl -s 127.0.0.1:4777/api/state` → `tokens` (`daily[{date, counted, cacheRead}]`, `today`, `week`, `month`, `updatedAt`)

## แจ้งเตือนบนเดสก์ท็อป

เปิดที่ **⚙️ → แจ้งเตือนบนเดสก์ท็อป** (ค่าเริ่มต้นปิด — เบราว์เซอร์จะถามสิทธิ์เฉพาะตอนกดปุ่มนี้ ถ้าถูกบล็อกหรือเบราว์เซอร์ไม่รองรับ จะบอกไว้ใต้ปุ่ม)

- กฎเดียวกับเสียง: เฉพาะตอนสถานะ **เปลี่ยนเป็น** รอคุณ / Error / ตอบจบเทิร์น, ไม่แจ้งตอนโหลดหน้า/reconnect, ต้องเชื่อมต่ออยู่, เลือกได้ว่าทุก session หรือเฉพาะที่ดูอยู่ (ค่าเดียวกับเสียง), session ละไม่เกิน 1 ครั้งต่อ 3 วิ (อันที่สำคัญกว่าแทรกได้)
- แจ้ง **เฉพาะตอนแท็บถูกซ่อนหรือไม่ได้โฟกัส** — ถ้าเห็นหน้าอยู่แล้ว ใช้เสียงอย่างเดียว
- ข้อความ: สถานะภาษาไทย + ชื่อโฟลเดอร์โปรเจกต์ + session id สั้น — ไม่มี prompt หรือผลลัพธ์เครื่องมือ
- แจ้งเตือนของ session เดียวกันแทนที่กัน (`tag`), คลิกแล้วกลับมาที่แท็บนี้และเลือก session นั้นให้
- ใช้ได้ในโหมด demo ผ่านปุ่มเดียวกัน (แจ้งจาก event จำลอง)

## มือถือ (จอแคบ ≤ 620 px ของห้อง)

- ลูกแมวตัวใหญ่ขึ้นและวางห่างขึ้น, พื้นที่แตะ ≥ 40×40 px, ป้ายชื่อย่อ (`Expl`, `GP`) — ชื่อเต็มอยู่ใน tooltip / aria-label
- บับเบิลของโต๊ะแสดงเฉพาะชื่อเครื่องมือจริง (ตัดคำได้ 2 บรรทัด) — แถวบนลอยเหนือหัวแมว, แถวล่างอยู่ใต้ป้ายชื่อ, ของ Luna อยู่ขวาของกระดานงาน; จำนวน agent ของ Nori ย้ายไปอยู่ในแถบสถานะด้านบน
- กระดานงานแสดงแค่จำนวนงาน + เลยกำหนด (เวลาวันนี้ดูที่ป้ายของแท็บ ⏱)
- โหมดมืด: ลูกแมว Main (สีดำ) มีขอบสว่างบาง ๆ

## ความปลอดภัยและความเป็นส่วนตัว

- Backend listen ที่ `127.0.0.1` เท่านั้น, ตรวจ `Host` header (กัน DNS rebinding), WebSocket รับเฉพาะ Origin ของ localhost
- `/hook` ปฏิเสธ request ที่มี `Origin` (เว็บอื่นในเบราว์เซอร์ยิงปลอมเข้ามาไม่ได้) และรับเฉพาะ JSON ≤ 1 MB
- **ไม่ส่ง** เนื้อหา prompt (แสดงแค่จำนวนตัวอักษร) และ **ไม่ส่ง** ผลลัพธ์ของเครื่องมือไปหน้าเว็บ
- สรุปเครื่องมือแบบสั้น: ชื่อไฟล์ (ไม่รวม path), ชื่อโปรแกรมของคำสั่ง Bash, hostname ของ URL
- ข้อความ error เก็บแค่ 2 บรรทัดแรก ≤160 ตัวอักษร และ redact ค่าที่ดูเหมือน password/token/API key/Bearer/URL credential
- ไม่อ่าน environment variables (ยกเว้น `REDMINE_URL` / `REDMINE_API_KEY` และตัวตั้งค่า `NEKO_*`), ไม่เขียน log ไฟล์, ไม่มี endpoint ใดรันคำสั่ง, หน้าเว็บส่งอะไรกลับมาก็ถูกเพิกเฉย
- hook ตอบ `{}` เสมอ → ไม่บล็อกหรือเปลี่ยนพฤติกรรม Claude; ถ้า backend ปิดอยู่ hook จะล้มแบบไม่บล็อกงาน

## ทรัพยากร (วัดจริงบนเครื่องนี้)

- Backend: RAM ~58 MB, CPU ~0.2% เฉลี่ย, dependency runtime ตัวเดียว (`ws`)
- หน้าเว็บ: JS 52 KB (gzip), heap ~4 MB, ตอนว่าง script ≈0.1 ms ต่อ 10 วินาที, แอนิเมชันรันเฉพาะตอนมีเครื่องมือทำงานจริง
- ไม่มี polling: backend push เมื่อมี event, นาฬิกา "x นาทีที่แล้ว" อัปเดตทุก 30 วิ และหยุดเมื่อแท็บถูกซ่อน
- รองรับ `prefers-reduced-motion` (ปิดแอนิเมชันทั้งหมด) และโหมดมืด

| ไม่เห็น SessionStart | Claude Code ไม่รัน HTTP hook สำหรับ SessionStart — installer จึงใช้ `curl` (command hook แบบ async) แทน ต้องมี `curl` ในเครื่อง |
| port 4777 ถูกใช้ | `NEKO_PORT=4800 npm start` และ `NEKO_PORT=4800 npm run hooks:install` |
| หลัง restart backend ไม่เห็น session เดิม | ปกติ — สถานะอยู่ใน memory; session ที่ยังเปิดอยู่จะกลับมาเมื่อมี event ถัดไป |
| อยากดู event ที่เข้ามา | `NEKO_DEBUG=1 npm start` (พิมพ์แค่ชื่อ event + session id สั้น + ชื่อ field ของ payload ไม่พิมพ์ค่า) |

## ถอนการติดตั้ง

```bash
npm run hooks:uninstall    # ลบเฉพาะ hook ของ Neko (สำรองไฟล์ก่อน)
```

หรือคืนไฟล์จาก backup: `cp ~/.claude/settings.json.bak-neko-<เวลา> ~/.claude/settings.json`

## โครงสร้าง

```
server/index.js        HTTP + WebSocket (127.0.0.1)
server/state.js        state machine ต่อ session + รายการ agent (Main + subagent) + activity ring buffer (100)
server/sanitize.js     สรุป/ตัด/redact payload
server/usage.js        อ่าน token usage จริงจาก transcript (.jsonl) ต่อ agent
server/tokens.js       tokens รายวันจาก transcript ทุกไฟล์ (สแกนครั้งเดียว + อ่านต่อทุก ~60 วิ ขณะมีหน้าเว็บ)
server/holidays.js     อ่าน/ตรวจ holidays.json (อ่านใหม่เมื่อ mtime เปลี่ยน)
server/redmine.js      ดึงงาน Redmine ที่ assign ให้ฉัน (เฉพาะตอนมีหน้าเว็บเปิดอยู่)
server/commits.js      git log ในเครื่อง → เลขงานที่ commit อ้าง เทียบกับเวลาที่ลง
server/claudetime.js   เวลาที่ Claude ทำงานต่อเลขงาน/วัน (เลขงานจาก prompt / branch / commit) เก็บใน claude-time.json
holidays.example.json  ตัวอย่างวันหยุดราชการไทย 2026 (วันที่ตายตัว) สำหรับคัดลอกไปแก้
scripts/install-hooks.js  ติดตั้ง/ถอน hooks พร้อมสำรอง
web/src/               React UI (Cat/Kitten SVG, ตำแหน่งลูกแมวใน office.js, Details, Activity Feed, demo.js สำหรับ ?demo=1 เท่านั้น)
```
